# 固定预览与再次按空格：方案

状态：**待确认的方案，尚未按本文修改固定窗口行为。**

## QuickLook 的做法

以下基于 Windows 版 [QL-Win/QuickLook 源码（dada5c3）](https://github.com/QL-Win/QuickLook/tree/dada5c3bfa7e20e969783a45e8c3d1bc9892028d)，不是对所有版本或所有系统的实机结论。

1. QuickLook 管理一个供空格键使用的活动预览窗口。普通窗口显示时，再按空格，若选中的还是同一文件（或没有选中项），则关闭活动预览；选中不同文件则切换内容。[窗口管理器](https://github.com/QL-Win/QuickLook/blob/dada5c3bfa7e20e969783a45e8c3d1bc9892028d/QuickLook/ViewWindowManager.cs#L76-L87)
2. 点“防止关闭”后，窗口管理器停止对旧窗口的跟随监听，将其标记为固定，然后创建新的活动窗口。旧窗口继续保留原内容，新窗口以后接收空格或选区切换。[固定与创建窗口](https://github.com/QL-Win/QuickLook/blob/dada5c3bfa7e20e969783a45e8c3d1bc9892028d/QuickLook/ViewWindowManager.cs#L100-L106)
3. **固定与置顶是两个不同按钮**：置顶改变窗口层级；固定用于保留预览。默认的失焦行为下，已经固定的窗口再次点击固定按钮会提示，而不是把另一个窗口自动固定。[按钮实现](https://github.com/QL-Win/QuickLook/blob/dada5c3bfa7e20e969783a45e8c3d1bc9892028d/QuickLook/ViewerWindow.xaml.cs#L72-L114)

## 本项目现状和问题

项目已有独立 `BrowserWindow` 和预热的活动窗口，固定 A 后预览 B 的基本结构已经存在；文件令牌、文件夹状态和关闭清理由各窗口持有。[当前实现](https://github.com/Chaoleme-Studio/quick_look_fast/blob/73a3032ae9f932d7effae3a860f0279127a2c212/electron/main.ts#L238-L272)

当前“固定”同时执行永久置顶；取消固定 A 时，如果活动窗口 B 可见，代码会把 B 自动设为固定。这与 QuickLook 的两个独立操作不同，也可能让新窗口被旧的置顶窗口遮挡，或让用户意外得到一个固定的 B。窗口层级和 DOpus 双栏仍需在真实桌面验证。

## 建议的交互

1. **固定 A**：A 保留文件、位置、缩放和内部状态，不再跟随文件管理器的选中项；准备一个活动窗口，但不创建第二个应用实例。
2. **空格预览 B**：活动窗口显示 B；A 不切换、不关闭。默认不抢资源管理器键盘焦点，并让 B 可见；优先使用活动窗口上次的位置，如果会被 A 大面积遮住，则在当前显示器可用区域内错开。
3. **继续使用空格和方向键**：活动窗口内切换选区、同一文件的开关及 Esc 只作用于活动预览；固定的 A 不受影响。继续固定 B 时可以再打开 C。
4. **固定和置顶分开**：图钉只负责保留预览，另设独立的置顶按钮或菜单，默认不置顶。若用户主动将 A 置顶，遵循系统窗口层级，同时尽量错开放置 B。
5. **取消固定 A**：只改变 A 的固定状态，不自动固定、关闭或替换 B。若 B 正在活动，保留 B 为活动窗口，A 暂时作为独立普通窗口保留；若没有活动预览，可让 A 恢复为活动窗口。关闭 A 时只释放 A 的内容和资源。

第 5 条是本项目的建议交互，并非声称 QuickLook 按此处理。是否采用单独的置顶按钮、取消固定后的具体规则，可在实现前依据用户习惯调整。

## 实现与验收要点

- 主进程明确区分“活动窗口”“固定窗口”和置顶状态；每个窗口保留自己的预览上下文，键盘桥接只向活动窗口转发。
- 预览请求按来源窗口和请求序号校验，防止文件管理器旧事件、异步读取或窗口关闭后的回调改变其他窗口。
- 新窗口位置使用目标显示器工作区，考虑多显示器、不同缩放比和屏幕边缘；不把所有窗口都叠在同一点。
- 验证 A 固定后打开 B、连续固定 A/B 后打开 C、重复空格、选区跟随、关闭任一窗口、取消固定、显式置顶以及文件夹/压缩包资源清理。
- Windows Explorer、桌面和 DOpus 单双栏分别实测焦点与窗口层级；macOS 和 Linux 的窗口管理器差异单独验证。
